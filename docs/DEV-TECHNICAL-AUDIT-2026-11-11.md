## 裁决

项目有可用的解析和浏览器回归，也有值得保留的防护；主要问题是同一册书有太多所有者、太多形态，导致状态一致性、安全边界和性能都靠补丁维持。上轮拆出 facade、Worker 请求协议和存储事务确实解决了部分问题，但文件移动没有让新书、缓存书、内置书和扩展打开走同一个交接契约。下一轮应重写交接边界，删掉负担最大的产品分支；不建议换框架或把可用的 EPUB 转换器从零写一遍。

## 待确认后的实施骨架

1. **锁行为与基线。** 从真实书和现有 fixtures 固化 TXT/EPUB 导入结果、目录/脚注/图片、历史定位、缓存重开、匿名书架行为；增加逆序打开、同名书、切换繁简、重复图片生命周期等缺口。性能记录同机器同样本多次测量，分冷启动和热缓存。
2. **先重写交接和身份。** 一个 OpenSession 持有取消与资源；解析返回 `BookDocument`，原书/派生缓存/用户进度分开；UI 只接收当前 session 的完整提交。先验证旧库迁移、失败和旧版本回退。保留现有解析算法作为行为对照。
3. **再减法与优化。** 按批准的取舍删除模式和功能；单一渲染入口，资源按 ID 管理。优先消掉候选全对全和分页重叠扫描。页码可派生，书签和进度使用稳定定位；变更断页算法需单独验收。50k 样本应按原约束实测，不能把本次微基准比例当成整本书提速承诺。
4. **收拢分发和设置。** 配置输入合并、运行时文本与主题分开；Web 和仍保留的发行目标用同一个依赖图；补可访问名称、迁移边界与目标平台验收。最后更新 AGENTS/台账并清理旧路径。

每一阶段都应能独立回滚。保留 EPUB 路径规范化与渲染白名单、搜索 Worker 的终止能力、事务 commit 确认、原书与缓存分离、元数据轻量列表和真实浏览器回归；它们解决的是真问题。未经选择，不执行功能删除和迁移。
