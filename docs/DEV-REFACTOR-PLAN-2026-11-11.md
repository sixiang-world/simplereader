### 较原方案的取舍

- 不批量复制/重建整个旧数据库。历史 `name` keyPath 保留；只给新导入独立 ID，旧书保留旧键。这减少迁移中断和复制原书的风险。
- 同一文件再次导入会新建副本，暂不做内容哈希去重或隐式替换。保守保留原件优于误覆盖。
- 删除旧逐字映射引擎与对应维护脚本/过期模式测试，改用真实 OpenCC 行为测试，包括错误回退和转换副本。旧转换后的缓存首次重开从原 File 重建。
- 保留离线预分页 CLI、旧扩展构建工具及历史文档，不在主线自动运行；保留用户资产与外部服务数据。

### 回退与数据保护

上线前备份原始书籍和浏览器站点数据。当前没有接触个人真实书库；浏览器回归使用临时隔离上下文。

本轮不升级 IndexedDB schema、不删除旧原件、旧进度、字体和设置。若回退代码，旧记录仍可读取；新 ID 记录在旧版本的名称显示/进度语义不保证兼容，故不能宣称无损双向降级。不要以删除站点数据处理回退。恢复旧源码可从审查基线 95f8722 建立独立检出；不要覆盖当前用户工作树。原文件始终是派生缓存失效后的恢复来源。
